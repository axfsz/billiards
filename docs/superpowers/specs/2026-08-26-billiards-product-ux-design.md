# 台球项目产品体验重构设计

## 目标

在不改变原生 Node.js 服务端权威边界、房间协议和台球规则实现的前提下，把现有单页游戏升级为普通用户无需阅读说明也能快速开始、邀请、加入、完成比赛并继续游玩的产品级 Web Game。

成功标准：首次用户在 10 秒内理解产品和开始方式，房主在 20 秒内完成邀请，被邀请者通过链接直接进入昵称确认与加入流程；比赛中始终知道当前玩家、目标球、犯规原因与网络状态；比赛结束后可自然再来一局或邀请新好友。

## 现状审计

### 页面状态地图

当前入口直接展示球桌，本地双人默认已开始；模式、规则、声音、在线对局、重开、僵局等操作集中在顶部。在线状态位于单一弹窗内，包含无房间、等待房间、已加入比赛三类界面。比赛状态由 `aim`、`charge`、`roll`、`placement`、`decision`、`over` 表示，在线房间另有 `WAITING`、`PLAYING`、`PAUSED`、`FINISHED`、`CANCELLED`、`EXPIRED`。

主要问题：产品入口缺失，邀请和加入混在技术型弹窗中；等待房间信息不足；当前回合虽有高亮但缺少强提示；网络、犯规和自由球信息主要依赖一行 HUD 或短 Toast；结果页信息单薄；设置与比赛操作层级混杂；文本没有统一国际化入口。

目标状态地图：

1. `HOME`：快速开始、邀请好友、加入房间三个主入口。
2. `JOIN_INVITE`：邀请链接识别后显示邀请者、玩法、昵称与单一加入按钮。
3. `LOBBY_WAITING`：房主、玩法、邀请码、链接、二维码、分享动作与玩家席位。
4. `GAME_LOCAL` / `GAME_ONLINE`：球桌、回合 HUD、目标与网络状态、轻量引导。
5. `BALL_IN_HAND`：合法区域、实时合法性、确认放置。
6. `NETWORK_PAUSED`：自己恢复中或对手离线的非技术化遮罩与倒计时。
7. `BILATERAL_DECISION`：重开、僵局、再来一局统一确认组件。
8. `RESULT`：胜负、昵称、比分、时长、进球、犯规、连杆与后续动作。
9. `SETTINGS` / `RULES`：声音、辅助线、振动、语言、帮助与退出。
10. `ERROR`：表单内错误、Toast 和阻断式对话框三层反馈。

### 用户旅程

- 本地双人：主页点击快速开始，默认中式八球并直接进入球桌；玩法可在开始前或设置中调整。
- 创建邀请：主页点击邀请好友，确认昵称后创建中式八球房间，进入完整等待房并分享。
- 链接加入：识别 `?invite=`，直接显示邀请详情与昵称，不要求再次输入邀请码；确认后进入比赛。
- 邀请码加入：主页点击加入房间，允许输入代码或粘贴完整链接并自动解析。
- 断线恢复：自己掉线显示自动重连；对手掉线显示暂停、倒计时和玩家身份；恢复后自动同步并提示比赛继续。
- 赛后再来一局：结果页发起统一确认请求；双方接受后保留房间与昵称并重置球局。

## 方案选择

### 方案 A：在现有单文件内建立产品壳层与逻辑分区（采用）

保留 `billiards.html` 的 Canvas、规则、物理与在线客户端，在其上增加首页、等待房、设置、网络遮罩、回合提示和结果面板。使用 CSS 变量与可复用 class 形成轻量设计系统，使用集中式文案表、设置状态和 UI 渲染函数约束新增代码。

优点是协议零迁移、部署方式不变、风险最低，适合当前测试体系。代价是文件仍然较大，但逻辑边界会比现在清楚。

### 方案 B：拆分原生 ES Modules

将 UI、i18n、online-client、audio 等拆成独立脚本。长期维护性更好，但当前服务端仅显式放行 `/assets/`，拆分会同时影响静态资源、CSP、测试与部署，扩大本轮风险。

### 方案 C：迁移框架

使用 React/Vue 重写产品外壳。组件能力强，但会引入构建系统和较大回归面，也违反本轮“不一次性重写、不引入大量依赖”的约束，因此不采用。

## 体验与组件设计

### 首页与导航

页面首次打开显示紧凑的产品首页，球桌作为背景信号但不进入可操作状态。三个入口按主次排列：快速开始、邀请好友、加入房间。快速开始直接进入中式八球本地双人；玩法选择作为次级控制。已有有效 session 时优先显示“继续比赛”。

邀请 URL 会进入专用加入状态。客户端先用受控的房间预览接口读取邀请元数据；若不新增公开预览接口，则显示通用邀请文案并在用户确认昵称后加入。为满足显示邀请者和玩法，本轮新增只读预览 API，返回严格裁剪后的邀请者昵称、玩法、状态和过期时间，不泄露房间或用户凭据。

### Invite Lobby

等待房显示双方头像占位、房主 READY、对手等待、玩法、邀请码和邀请链接。提供复制链接、复制邀请码、系统分享、WhatsApp、Telegram 与二维码。微信内显示复制提示。所有异步按钮拥有 loading、disabled 和成功/错误反馈。

二维码优先使用轻量、无依赖的 Canvas 编码实现；若实现成本会威胁 P0/P1，则保留可扫描 QR 的独立小模块，并以复制链接为可靠兜底。

### 比赛 HUD 与输入

桌面端保持三段式 HUD，移动端压缩为双玩家卡加中央回合条。当前玩家除颜色外同时显示“你的回合/对方回合”文字、状态徽标和约 1 秒非阻断回合横幅。HUD 显示昵称、球组/比分、剩余目标球、自由球、犯规与在线状态。

桌面继续采用鼠标瞄准与按住蓄力，增加始终可读的力度百分比。移动端保留拖动角度与独立力度条、击球按钮，扩大触摸目标并锁定比赛区滚动。辅助线设 `OFF`、`SHORT`、`NORMAL`，默认 `NORMAL`，由设置持久化。

### 反馈、自由球与网络

犯规反馈采用结构化 Toast：标题、原因、结果；重要结果同步写入持续 HUD。自由球继续使用红绿合法性视觉，并补充固定操作条与确认/恢复按钮。

网络状态统一为正常、较慢、断线、恢复中。技术错误只写 console，用户界面映射为可操作的中文或英文提示。对手离线时覆盖球桌并显示等待倒计时；自己断线时显示恢复中，成功后自动关闭并展示“比赛已恢复”。

### 双方确认与赛果

重开、僵局、再来一局继续复用现有 decision modal 与服务端请求协议，统一文案、主次按钮、请求方等待和取消状态。

结果面板显示胜负、双方昵称与比分、比赛时长、击球数、进球数、犯规数和最大连续进球。主操作为再来一局，次操作为邀请新好友、复制结果、系统分享和返回首页。统计只由本地权威球局产生，并随 snapshot 同步时保持向后兼容；本轮不将统计新增为服务端验证字段。

### 设置、国际化与新手引导

设置弹窗包含声音、辅助线、振动、语言、规则和退出本局。设置保存于 localStorage。核心产品文案集中在 `I18N` 字典，支持 `zh-CN` 和 `en`，按浏览器语言初始化并允许手动切换。规则细节、动态规则原因通过稳定 key 映射，不把服务器技术消息直接展示。

首次进入本地或在线球桌显示最多三步的非阻断引导：拖动瞄准、调整力度、击球。完成或跳过后持久化。

## 架构边界

- 服务端保留 session、room、WebSocket、snapshot、幂等、鉴权、限流、CSP、持久化和回合验证。
- 新增邀请预览为只读 HTTP 路由，只返回加入前必需字段并复用邀请有效性判断与限流。
- 客户端新增 `UI_STATE`、`I18N`、`SETTINGS`、`METRICS` 和比赛统计对象；规则与物理函数保持原位置和接口。
- UI 更新通过少量集中函数完成：`showView`、`renderHome`、`renderInviteJoin`、`renderOnlineLobby`、`refreshHud`、`renderNetworkState`、`renderResult`。
- `trackEvent(name, payload)` 默认 console/no-op，仅允许文档列出的事件名，不发出网络请求。

## 错误与可访问性

- 表单校验显示在字段附近；可恢复操作使用 Toast；会终止房间或比赛的情况使用 modal。
- 所有 modal 实现 Escape、焦点进入、焦点循环和关闭后焦点恢复；Enter 触发表单主操作。
- 按钮和图标均有可读名称，状态不用颜色单独表达，触摸目标不小于 44px，正文与背景满足基本对比度。
- 网络按钮防重复提交；WebSocket 重连只保留一个计时器；DOM 状态改变时避免在每帧重复更新。

## 测试与验收

1. 保持服务端和现有 UI 单元测试全部通过。
2. 新增静态 UI 测试覆盖首页、i18n、设置、Lobby、网络遮罩、结果页和核心可访问性结构。
3. Playwright 在 1366x768、1440x900、1920x1080、375x667、390x844、393x852、430x932 验证无溢出、遮挡和空白 Canvas。
4. 两个独立 browser context 完成创建、链接加入、双方连接、轮流击球、断线暂停、恢复和 rematch 请求状态流。
5. 检查浏览器 console，无未处理异常；确认本地双人、自由球、犯规、结果与重新开始可操作。
6. 最终运行 `npm test`，再检查干净启动与 `/healthz`。

## 实施顺序

1. 固化设计系统、首页壳层和页面状态，不触碰规则与协议。
2. 重构邀请加入和 Waiting Lobby，必要时增加只读邀请预览。
3. 强化 HUD、回合提示、犯规、自由球和网络恢复 UI。
4. 完成结果面板、设置、i18n、引导和埋点接口。
5. 补充服务端、UI 与双客户端测试，按桌面和移动矩阵修复问题。

## 非目标

- 不引入账户系统、排行榜、第三方分析或收费 API。
- 不迁移前端框架，不重写物理和规则引擎。
- 不改变客户端非权威、服务端校验与匿名 Cookie 身份模型。
- 不承诺跨公网 NAT、生产域名、证书或第三方分享平台的可用性。
